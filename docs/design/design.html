2. Typography

Two font families only: Inter (all UI and English text) and Scheherazade New (all Quranic Arabic text). Amiri is kept as a local backup but is not loaded by the app.

Font Pairing & Loading Strategy

Family Role Format font-display Fallback stack
Inter (variable) UI, labels, English copy, metadata Variable TTF → woff2 (via next/font) swap — text always visible ‘Segoe UI’, Arial, sans-serif
Scheherazade New Quranic Arabic display text 4 weights · subsetted woff2 optional — no layout shift; fallback if slow ‘Amiri’, serif

Why optional for Arabic? Quranic Arabic text is large (2–4rem). Loading it with swap would cause visible font swap flash on first load. optional shows fallback on first load and the correct font from cache on every subsequent visit — no layout shift ever.

Why Scheherazade New? Purpose-built for Quranic Arabic — comprehensive diacritic (tashkeel/harakat) support, optimised for Uthmani script rendering. Cleaner single family (4 weights) vs Amiri. Better for a Quranic vocabulary app.

Arabic Font Subsetting

Scheherazade New is subsetted using pyftsubset (fonttools) against the full Quranic Unicode range before shipping. Run once from the project root: npm run subset-fonts. Output: public/fonts/Scheherazade_New/ScheherazadeNew-{weight}-quran-subset.woff2.

Rules

  • Use var(--font-size-arabic) for all Arabic text elements — never hardcode a size.
  • Arabic text always has dir="rtl" and lang="ar".
  • Use font-family: var(--font-scheherazade), 'Amiri', serif for Arabic.
  • Use font-family: var(--font-inter), 'Segoe UI', Arial, sans-serif for UI/English.
  • Do not load Amiri or static Inter weight files in the app — one variable Inter + subsetted Scheherazade New only.
  • Run npm run subset-fonts once before building for production. Re-run only if the glyph inventory changes.

7. Accessibility

Ensure all UI meets WCAG AA contrast, keyboard navigation, ARIA labeling, and visible focus states.

  • Focus: On light surfaces, use the deeper brass focus token with a clear 3px ring; on dark surfaces, use the lifted brass token for the same visible emphasis.

Reduced Motion

All transitions and animations must respect prefers-reduced-motion: reduce. Under this media query, set transition: none and animation: none globally. For the shimmer skeleton, replace the gradient sweep with static grey blocks. 

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    transition: none !important;
    animation: none !important;
  }
  .skeleton-block { background: var(--color-surface-alt); }
}

Phase 4.3: Theme & Tokens — Dark Mode, ThemeProvider & Tailwind

This section specifies the implementation contract for dark mode activation, the ThemeProvider setup, and the Tailwind v4 @theme mapping. All implementation is downstream from this specification.

Dark Mode Activation: .dark Class on <html>

Dark mode is activated by adding the .dark class to the <html> element. This causes the CSS variables in the .dark {} override block (see below) to take effect globally, remapping all semantic tokens to their dark-palette values.

  • Library: next-themes manages the class toggle, localStorage persistence, and system preference sync.
  • Attribute: attribute="class" — next-themes adds/removes the dark class on <html>.
  • Default: defaultTheme="system" — respects prefers-color-scheme on first visit.
  • localStorage key: "theme" (next-themes default). Stored value is "light", "dark", or "system".
  • FOUC prevention: next-themes injects a small blocking script before React hydration — no flash of wrong theme.
  • System sync: When stored as "system", theme tracks prefers-color-scheme changes in real time.

ThemeProvider Setup (app/layout.tsx)

// app/layout.tsx
import { ThemeProvider } from 'next-themes'

export default function RootLayout({ children }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      </body>
    </html>
  )
}

suppressHydrationWarning on <html> is required — next-themes modifies the class attribute server-side vs. client-side.

ThemeToggle Component Spec

  • Placement: Header, top-right corner, inside the nav row.
  • Size: 40×40px icon button, border-radius: 0.5rem, transparent background, 1.5px solid var(--color-border) border.
  • Icon convention: Shows the target mode — not the current mode.
    • Currently light: show Moon icon (aria-label: "Switch to dark mode")
    • Currently dark: show Sun icon (aria-label: "Switch to light mode")
  • Transition: Use var(--transition-base) on hover/focus states.
  • ARIA: aria-label on <button>; aria-hidden="true" on the icon SVG.

Tailwind v4 @theme Mapping

Tailwind CSS v4 uses an @theme {} inline block in CSS (replacing the tailwind.config.js theme object) to declare design tokens that become Tailwind utility classes. The following block maps the project's CSS variables to Tailwind utilities via --color-* namespace. Add this to app/globals.css after the @import 'tailwindcss' line and before @layer base. 

@theme {
  /* Map shadcn CSS variables → Tailwind utility classes */
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-card: var(--card);
  --color-card-foreground: var(--card-foreground);
  --color-popover: var(--popover);
  --color-popover-foreground: var(--popover-foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-secondary: var(--secondary);
  --color-secondary-foreground: var(--secondary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-accent: var(--accent);
  --color-accent-foreground: var(--accent-foreground);
  --color-destructive: var(--destructive);
  --color-destructive-foreground: var(--destructive-foreground);
  --color-border: var(--border);
  --color-input: var(--input);
  --color-ring: var(--ring);
  --radius-sm: calc(var(--radius) - 2px);
  --radius-md: var(--radius);
  --radius-lg: calc(var(--radius) + 2px);
  --radius-xl: calc(var(--radius) + 4px);
}

This generates Tailwind utility classes: bg-background, text-foreground, bg-primary, text-primary-foreground, bg-muted, text-muted-foreground, border-border, ring-ring, bg-card, text-card-foreground, bg-destructive, text-destructive-foreground, rounded-sm/md/lg/xl, etc.

Note: Extended project tokens (--color-primary-strong, --color-surface-arabic, etc.) are accessed directly via var() in component CSS — they do not need @theme entries unless Tailwind utility classes are needed for them.

Integrated Result Card

The implementation unit is a single result card: WordCard provides the outer structure, RootDisplay sits inside the meaning block, AudioPlayer is the first interactive control, and VerseList expands beneath the card content. These components should be reviewed as one reading flow, not as isolated primitives.

Integrated Structure

  • WordCard shell: rounded card, soft raised surface, Arabic headline first, supporting transliteration and English gloss directly below.
  • RootDisplay placement: root pills remain visually tied to the lexical meaning block, not detached into a separate footer.
  • AudioPlayer row: sits above the occurrences divider so playback is available before the user opens VerseList.
  • VerseList region: collapsed by default, then expands inline below the separator using --transition-panel.

Loading Handoff

Loading stays defined by the existing Skeleton (WordCard shimmer) demo above. The handoff rule is simple: skeleton shape matches the WordCard layout, then content swaps in-place so the result card does not jump when Arabic text, RootDisplay pills, AudioPlayer, and VerseList metadata appear.

Accessibility Notes

  • Arabic text: set lang="ar" and dir="rtl" on Arabic headline and verse text regions; surrounding UI remains LTR.
  • Button labels: AudioPlayer labels should expose the action, not the icon name: “Play audio for …”, “Pause audio for …”, “Retry audio for …”.
  • Result announcement: when a search resolves, announce the result count through a nearby role="status" / aria-live="polite" region while keeping keyboard focus in the SearchBox.
  • Focus order: SearchBox remains first, then the next Tab target is AudioPlayer, then the VerseList trigger, then verse items if expanded.
  • Collapsible semantics: VerseList trigger uses button, aria-expanded, and aria-controls; move focus to the first verse item only on explicit expand by keyboard.
  • Reduced motion: keep VerseList open/close and loading shimmer aligned with prefers-reduced-motion: reduce; remove non-essential animation, keep state changes instant.

  3. Arabic regions are explicitly marked for RTL and language, and button labels describe the user action.
  4. Result announcement, focus order, collapsible semantics, and reduced-motion handling are clear enough to implement without further design guesswork.

Meta: Frameworks, Packages & Conventions

  • No external CSS/JS frameworks (e.g., Tailwind, shadcn, Bootstrap, Material UI) are used in this design reference file; all styles are custom CSS. The production app uses Tailwind CSS v4, shadcn/ui (new-york style), and lucide-react as documented in Sections 9 and 12.

  • No external UI or animation packages are referenced; all interactivity is native HTML/CSS.
  • All responsiveness is handled by the custom CSS in this file. For new UI elements, use the documented class patterns (e.g., .component-box, .input-demo, .card-demo, .pill-row, .motion-demo, etc.) or wrap in a responsive container.
